# Workplan 目录与选用规则

更新日期：2026-08-05

## 作用

`docs/workplans/` 保存跨模块实现、公共契约变更、正式评测和训练阶段的临时实施方案。
这些文件记录“该阶段准备怎样做以及实际怎样变化”，不是当前项目状态或永久路线图。

## 从哪里确定要读取哪份方案

唯一入口是 `docs/ACTIVE_PLAN.md` 的“当前实施依据”：

1. 如果该节列出一个精确 workplan 路径，当前任务必须完整读取并遵循该文件。
2. 如果该节写明没有活动 workplan，则本目录中的已完成文件都不自动适用。
3. 已完成方案只在以下情况按需读取：用户明确指定；审计对应历史阶段；当前源码意图无法
   从代码、状态和长期决策确定；新计划需要复用已验证的接口或失败结论。
4. 新的大范围任务不能直接“恢复”旧方案。应以当前代码和状态重新确认缺口，建立新的
   workplan，再由 `ACTIVE_PLAN.md` 登记为唯一活动依据。

因此，文件名或历史对话都不能决定当前方案；`ACTIVE_PLAN.md` 的精确引用才可以。

## 文件要求

活动 workplan 至少写明：

- 当前缺口和已验证基线；
- 已确定方案、模块边界与接口契约；
- 修改文件、依赖、迁移策略；
- 本地/服务器资源边界；
- 验收测试和停止条件；
- 方案发生变化时的变更记录。

阶段完成后必须更新稳定状态/决策、修改本索引状态，并从 `ACTIVE_PLAN.md` 移除活动引用。
已完成方案正文保留为历史证据，不继续追加下一阶段任务。
